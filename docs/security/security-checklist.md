# 等保三级安全设计清单（Phase 0）

> 本清单是**设计目标 + 预留审计接口**，不构成"已通过测评"的声明。正式测评以实际部署环境、测评范围和测评结果为准。参考 GB/T 22239 等保基本要求，标注每项由「应用代码 / 基础设施 / 运维制度」哪一方承担。

## 责任划分图例

- **应用**：由本项目代码实现（Phase 1 内完成）。
- **基建**：操作系统、网络、云平台、安全设备（如 WAF、堡垒机、日志审计系统）。
- **制度**：运维/管理制度、流程（如定期备份演练、账号审批）。
- **预留**：Phase 1 先留接口/字段，正式测评前接入。

## 1. 身份鉴别

| 要求 | 责任 | 落地 |
|---|---|---|
| 管理员唯一标识、口令复杂度与单向哈希 | 应用 | 密码 bcrypt/argon2，禁止明文 |
| 登录失败锁定、防暴力破解 | 应用 | 30 分钟 7 次 / 24 小时 10 次，账号+IP；登录接口限流 |
| 登录二次验证 | 不要求 | 后台仅账号+密码登录（产品已裁决）；正式测评如需再加 |
| 会话超时与登出撤销 | 应用 | JWT 8h + 黑名单撤销 |
| 登录行为审计（IP/时间/客户端） | 应用 | 记录登录事件进审计日志 |
| 多因素/双因素认证（测评可能要求） | 预留 | 预留 MFA 接口 |

## 2. 访问控制

| 要求 | 责任 | 落地 |
|---|---|---|
| 最小权限、角色分离 | 应用 | RBAC（角色/权限/数据权限） |
| 超级管理员全权限兜底 + 防降权 | 应用 | 受保护 `is_super_admin`，后端强制校验 |
| 后端接口级强制鉴权 | 应用 | 每受保护 API 校验，不只靠前端菜单 |
| 管理接口网络访问限制 | 基建 | 防火墙/安全组限制管理段 |
| 数据权限（全部/仅本人） | 应用 | Phase 1 两档，指定范围延后 |

## 3. 安全审计

| 要求 | 责任 | 落地 |
|---|---|---|
| 操作日志完整（操作者/时间/IP/模块/前后数据/结果） | 应用 | `audit_logs` 不可删除，保留 ≥180 天 |
| 日志查询/筛选/导出 | 应用 | System 模块 |
| 日志集中管理与防篡改 | 基建 | 日志审计系统（如 ELK/Loki/云日志） |
| 时钟同步 | 基建 | NTP |

## 4. 入侵防范

| 要求 | 责任 | 落地 |
|---|---|---|
| 最小安装、关闭多余服务 | 基建 | 主机加固 |
| 漏洞管理（PHP/Laravel/依赖升级） | 应用+制度 | composer/npm 定期审计；PHP 8.5 活跃支持 |
| 恶意代码防范、Web 防护 | 基建 | WAF、IDS/IPS |
| 异常登录检测 | 应用（预留） | 预留异常登录规则接口 |

## 5. 通信与数据完整性

| 要求 | 责任 | 落地 |
|---|---|---|
| 传输加密 HTTPS | 基建 | 全站 TLS |
| 固件包 SHA256 + 数字签名 | 应用 | 上传算 SHA256、离线签名、保存时二次校验 |
| 数据完整性校验 | 应用+基建 | 校验和、数据库约束 |
| 敏感数据脱敏 | 应用 | 手机号/邮箱脱敏展示 |

## 6. 数据保密性

| 要求 | 责任 | 落地 |
|---|---|---|
| 密码单向哈希、私钥不落库/日志/响应 | 应用 | 私钥离线保管 |
| 敏感数据存储加密（测评可能要求） | 预留 | 预留字段加密方案 |
| 数据备份加密 | 基建 | 备份加密 |

## 7. 备份恢复

| 要求 | 责任 | 落地 |
|---|---|---|
| 定期备份（数据库/对象存储/配置） | 基建+制度 | PostgreSQL + OSS 备份策略 |
| 恢复演练 | 制度 | 定期演练记录 |
| 异地/冗余 | 基建 | 云厂商多可用区 |

## 8. 剩余风险

- 正式测评需在**真实部署环境**上，由测评机构确定范围；本清单的「基建」「制度」项需运维与管理制度配合，非代码可完成。
- 云厂商 TBD 会影响 WAF、日志审计、堡垒机等选型，待定。
